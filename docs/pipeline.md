# Pipeline documentation

This document describes the full data pipeline behind DualCite, from raw
publications to the interactive views. It is written to double as an appendix
for the accompanying thesis.

## Overview

The pipeline has two halves. The **collection half** (source-specific research
scripts, `data-collection/`) turns published proceedings into a corpus of PDFs
and two paper-list JSON files. The **analysis half** (the `dualcite` package)
turns those into a precomputed index and two interactive visualizations.

```
publications ─► paper lists (JSON) ─► PDFs ─► GROBID XML ─► index ─► views
   collection half                              analysis half
```

## 1. Defining the two groups

Two groups of venues are compared. In the bundled example:

- **Cluster A — Computational Linguistics:** ACL, EMNLP, COLING, IJCNLP, NAACL,
  LREC, EACL
- **Cluster B — Information Retrieval:** SIGIR, WWW, CIKM, WSDM, ECIR, CHIIR

All membership is declared in `config.yaml`; nothing is hard-coded in the
analysis code.

## 2. Collecting paper lists

CL papers come from the ACL Anthology, which exposes a clean, open, structured
listing. IR papers come from DBLP and Crossref for the ACM-published venues.
The result is two JSON files, one per cluster, each paper carrying at least an
id, venue, title, and (where available) DOI.

## 3. Downloading PDFs

CL PDFs are open access and download directly from the ACL Anthology. IR PDFs
are mostly paywalled (ACM); they are retrieved either from open-access copies
(Unpaywall / OpenAlex / arXiv) or, where the user has institutional access,
through an authenticated browser session. See `data-collection/README.md` for
the legal considerations.

## 4. GROBID extraction

Each PDF is processed by a local [GROBID](https://github.com/kermitt2/grobid)
server in two passes:

- `processReferences` → a TEI XML list of the paper's bibliography, saved to
  `refs_xml/<cluster>/`.
- `processHeaderDocument` → a TEI XML header including author affiliations,
  saved to `headers_xml/<cluster>/`.

Each cluster's XML is kept in its own subfolder (`a/`, `b/`), so the two groups'
data stays physically separate.

One detail matters: GROBID must be sent an `Accept: application/xml` header, or
it returns BibTeX for the references endpoint instead of TEI. The runner does
this automatically.

## 5. Citation matching

For each paper, every extracted reference is matched back against the corpus:

1. **By DOI** when the reference carries one.
2. **By normalised title** otherwise — titles are lower-cased, stripped of
   punctuation and stop-words, then compared. Because most references have no
   DOI, a fuzzy comparison (rapidfuzz, ratio ≥ 85 by default) handles small
   extraction differences.

A citation is recorded only when its target resolves to another paper in the
corpus. Each resolved citation is then classified by direction — within cluster
A, within cluster B, A→B, or B→A.

## 6. Affiliation extraction

From each header XML, author countries and institutions are extracted.
Countries are normalised to ISO alpha-2 codes, with handling for GROBID quirks
(e.g. institution names appearing inside `<country>` tags). Counting is "full
counting": a paper with authors from several countries contributes to each.

## 7. Index and caching

Everything above is computed once and cached to
`data/.precomputed/index.json`. The index holds the papers, the resolved
citation edges, the affiliations, and the aggregate flow counts. Filter changes
in the UI re-aggregate cached counts rather than recomputing from XML, which
keeps both views responsive.

## 8. Visualization

- **Citation Graph** (Dash + Cytoscape): papers as nodes sized by in-corpus
  citations, edges coloured by direction, a server-computed layout with two
  topologies (mixed, or A/B split), and node-level detail on click.
- **Geo Map** (Dash + Plotly): a choropleth of author affiliations with
  log/linear scaling, several projections, and per-country detail panels.

Both read from the same cached index and the same shared venue selection.

## Reproducing the example corpus

The bundled data can be regenerated by running the collection scripts for the
target year, downloading the PDFs, running `dualcite.grobid_runner`, and
launching `dualcite.app`. Coverage will vary with PDF availability and GROBID
version.
